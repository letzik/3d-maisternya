## Ідея блоку

Перш ніж будувати щось своє, варто відповісти на нудне, але важливе питання: де я взагалі перебуваю на цьому екрані? Blender відкривається великою кількістю кнопок, панелей і крихітних іконок, і спроба запам’ятати їх усі наперед — гарантований спосіб розчаруватися ще до першого кубика. Хороша новина: реально потрібно **чотири зони екрана й кілька звичок**, а решта прикладається сама, коли трапляється нагода.

Цей блок не про те, «що робить кожна кнопка». Він про те, як не загубитися: як покрутити модель, щоб побачити її з потрібного боку; як точно вибрати саме ту грань, яку треба; де шукати назву об’єкта, коли їх на сцені вже десять; де подивитися чи змінити точні числа замість того, щоб тягнути мишею навмання. Ці навички не належать жодному конкретному інструменту з наступних блоків — вони працюють під усіма ними одразу.

::: idea Чотири зони, які варто впізнавати з першого погляду
**В’юпорт** (велика центральна область) — тривимірна сцена. **Ієрархія об’єктів** (Outliner, верхній правий кут) — список усього, що на сцені є. **Властивості** (Properties, нижній правий кут) — набір вкладок з деталями обраного об’єкта. **Заголовок режиму** (зверху над в’юпортом) — перемикач між Object Mode і Edit Mode та вибір, що саме виділяти.
:::

## Заняття 1 — в’юпорт, виділення, ієрархія й панелі

Відкрий Blender. За замовчуванням на сцені вже є куб, камера і джерело світла — не видаляй їх поки що, вони знадобляться як орієнтир для перших рухів мишею.

### Навігація у в’юпорті

В’юпорт — це не «фото» сцени з одного боку, а вікно в тривимірний простір, яке можна крутити, посувати й наближати будь-як. Головна відмінність від звичних 2D-програм: тут немає одного «правильного» кута огляду, і перша звичка, яку варто напрацювати, — постійно рухати камеру, а не намагатися все зробити з одного випадкового ракурсу.

| Дія | Миша | Що відбувається |
|---|---|---|
| Обертання (orbit) | Затиснути середню кнопку миші (СКМ) і водити | Камера обертається навколо точки, на яку зараз дивиться |
| Панорамування (pan) | [[key:Shift]] + СКМ, і водити | Камера зсувається вбік чи вгору-вниз, кут не змінюється |
| Наближення (zoom) | Колесо миші чи [[key:Ctrl]] + СКМ | Камера ближче чи далі від сцени |
| Показати все | [[key:Home]] | В’юпорт сам підбирає масштаб, щоб усі об’єкти влізли в кадр |
| Наблизитись до обраного | [[key:.]] (крапка на нампаді) чи «View → Frame Selected» | Камера центрується саме на виділеному об’єкті, ігноруючи решту сцени |

Якщо об’єкт «загубився» — виліз за межі видимої області чи виявився мікроскопічним — не шукай його вручну прокруткою. Просто [[key:Home]] повертає огляд до розумного стану.

### Осі й гізмо орієнтації

У правому верхньому куті в’юпорту є маленька кулька з шістьма підписаними кружечками — X, Y, Z та їхні протилежні напрямки. Це гізмо орієнтації, і воно виконує дві ролі одночасно.

По-перше, воно завжди показує, куди зараз «дивиться» камера відносно тривимірних осей: червоний — X, зелений — Y, синій — Z (це кольорове кодування повторюється всюди в Blender, тож варто запам’ятати його одразу). По-друге, по кожному кружечку можна клікнути — і камера миттєво перестрибне на строго ортографічний вид уздовж цієї осі (вигляд точно спереду, точно збоку, точно зверху). Це швидше й точніше за спробу «докрутити на око».

Той самий результат дає нампад клавіатури, якщо він є: [[key:1]] — вид спереду, [[key:3]] — вид збоку, [[key:7]] — вид зверху, [[key:Ctrl]] + та сама цифра — вид з протилежного боку, [[key:5]] — перемикання між перспективою і ортографічною проєкцією. На ноутбуці без нампада той самий набір відкриває пункт меню «View → Viewpoint» або комбінація з [[key:~]] (тильда), яка викликає кругле меню швидкого вибору виду.

::: tip Навіщо взагалі перемикатися на строгі види
Коли моделюєш щось симетричне (а в [[block:1]] це буде майже завжди), найлегше помітити перекіс саме з чіткого виду точно спереду чи точно зверху — під довільним кутом ока легко обманюються.
:::

### Виділення: об’єкти й елементи сітки

Виділення в Blender працює на двох різних рівнях, і плутанина між ними — найчастіша причина, чому «інструмент не працює».

**Object Mode** — рівень цілих об’єктів. Клік лівою кнопкою миші по об’єкту виділяє його цілком (обводиться помаранчевим контуром). [[key:Shift]] + клік додає ще один об’єкт до виділення. Клік по порожньому місцю чи [[key:Alt]] + [[key:A]] знімає виділення з усього.

**Edit Mode** — рівень геометрії всередині одного об’єкта: вершини, ребра, грані. У нього заходять клавішею [[key:Tab]], перебуваючи в Object Mode над потрібним об’єктом; та сама клавіша повертає назад. Усередині Edit Mode є три режими виділення — перемикаються клавішами [[key:1]], [[key:2]], [[key:3]] (без нампада, це основні цифри над буквами) або трьома іконками у верхньому лівому куті в’юпорту: вершини, ребра, грані відповідно.

| Гаряча клавіша | Дія |
|---|---|
| [[key:A]] | Виділити все |
| [[key:Alt+A]] | Зняти виділення з усього |
| [[key:B]] | Прямокутне виділення — затиснути й обвести рамкою |
| [[key:Shift]] + клік | Додати елемент до вже виділеного |
| [[key:Tab]] | Перемкнути Object Mode ↔ Edit Mode |
| [[key:1]] / [[key:2]] / [[key:3]] (в Edit Mode) | Вершини / Ребра / Грані |

Практичне правило, яке рятує в дев’яти випадках із десяти: якщо інструмент «нічого не робить», перевір по черзі — (1) я точно в Edit Mode, а не в Object Mode? (2) щось точно виділено, не порожньою множиною? (3) я в тому режимі виділення (вершини/ребра/грані), який очікує цей інструмент?

### Ієрархія об’єктів (Outliner)

Панель у верхньому правому куті — це список усього, що є на сцені, у вигляді дерева: колекції, у них об’єкти, у об’єктів — їхні дані (сітка, модифікатори, матеріали). Клік по імені об’єкта в Outliner виділяє його у в’юпорті так само, як клік по самому об’єкту, — це зручно, коли потрібний об’єкт заслонений іншими або дуже маленький.

Іконка ока навпроти кожного об’єкта ховає чи показує його у в’юпорті, не видаляючи, — зручно тимчасово прибрати зайве з поля зору, не боячись щось втратити. Подвійний клік по імені дозволяє перейменувати об’єкт прямо тут.

::: tip Перейменовуй одразу, не наприкінці
Звичка одразу давати об’єктам і матеріалам зрозумілі імена (не «Cube.003», а «Корпус» чи «Крило_ліве») здається дрібницею на самоті за одним об’єктом, але рятує, коли на сцені їх стає десять і більше — це знадобиться вже в [[block:2]], де складна модель збирається з кількох частин, і критично важливо в [[block:7]], де порядок і назви об’єктів впливають на те, що саме й у якому вигляді потрапляє в експортований файл.
:::

Коли на сцені кілька об’єктів утворюють один логічний виріб (кузов і колеса машини, тулуб і кінцівки персонажа), в Outliner видно й батьківсько-дочірні зв’язки (parenting) — про це докладніше в [[block:6]], де ієрархія стає основою для рігу.

### Панелі властивостей

Вертикальний стовпчик дрібних іконок у нижньому правому куті — це вкладки редактора Properties. Кожна відкриває інший набір налаштувань для того самого виділеного об’єкта. На перших порах реально важливі лише кілька:

| Іконка | Вкладка | Що там |
|---|---|---|
| Помаранчевий квадрат | Object Properties | Точні числові значення Location, Rotation, Scale — коли треба поставити рівно 0 чи повернути точно на 90°, а не крутити мишею на око |
| Зелений трикутник із крапками | Object Data Properties | Дані самої сітки: наприклад, тут вмикається відображення нормалей |
| Гайковий ключ | Modifier Properties | Стек модифікаторів об’єкта — саме тут у [[block:1]] додається Mirror |
| Кулька в шаховому візерунку | Material Properties | Матеріали й кольори граней — вона вже з’являється у [[block:1]], коли фарбуєш готовий об’єкт |

Панель Object Properties (помаранчевий квадрат) варто запам’ятати окремо: там знаходяться числові поля Location X/Y/Z, Rotation X/Y/Z, Scale X/Y/Z. Мишею (клавіші [[key:G]], [[key:R]], [[key:S]] — Move, Rotate, Scale) зручно рухати об’єкт «на око», а тут — виставити точне значення чи побачити, що об’єкт випадково повернутий на 47°, а не рівно на 45°.

### Модифікатори — загальна ідея

Гайковий ключ у стовпчику Properties відкриває вкладку Modifier Properties. Модифікатор — це операція, яка **не змінює саму сітку одразу й назавжди**, а накладається зверху як прозорий шар: об’єкт у в’юпорті виглядає так, ніби операція вже застосована, але під капотом початкова геометрія лишається недоторканою, і будь-який модифікатор можна вимкнути, змінити чи видалити без наслідків для базової форми.

Це і є те, чим у [[block:1]] виявиться Mirror: додаєш модифікатор Add Modifier → Generate → Mirror, і половина об’єкта починає дзеркалитися в реальному часі, поки ти редагуєш лише другу половину. Два ока навпроти кожного модифікатора в списку керують тим, чи видно ефект у в’юпорті окремо від того, чи видно він на фінальному рендері, — корисно для тимчасового вимкнення важкого модифікатора без втрати налаштувань. Кнопка Apply «запікає» модифікатор у саму сітку назавжди — це вже дія без легкого відкату, тож на початкових блокаутах поспішати з Apply не варто.

::: checkpoint
Відкрий Blender із чистої сцени. Обертай, панноруй і наближай в’юпорт мишею, перейди до строго вигляду спереду й зверху через гізмо або нампад, зайди в Edit Mode кубом і по черзі виділи все вершинами, ребрами, гранями, знайди куб в Outliner і перейменуй його, відкрий Object Properties та подивись його точні Location/Rotation/Scale.
:::

## Типові проблеми

| Проблема | Чому так сталося | Рішення |
|---|---|---|
| В’юпорт крутиться не мишею, а виділяє чи рухає об’єкт | Затиснута не та кнопка миші (ліва замість середньої) | Обертання — це саме середня кнопка миші (СКМ), затиснута й утримувана |
| Об’єкт «зник» із поля зору | Випадкове панорамування чи зум віддалили вигляд задалеко | [[key:Home]] показує всю сцену заново |
| [[key:G]]/[[key:R]]/[[key:S]] чи інструмент із таблиці нижче не діють на сітку | Ти в Object Mode, а операція очікує Edit Mode (або навпаки) | Перевір заголовок режиму над в’юпортом; [[key:Tab]] перемикає |
| Виділив явно не те, що хотів | Активний неправильний режим виділення (вершини/ребра/грані) в Edit Mode | Перемкни режим виділення клавішами [[key:1]]/[[key:2]]/[[key:3]] і повтори |
| Не можу знайти потрібний об’єкт серед багатьох на сцені | Об’єкт заслонений іншими або поза кадром | Клікни по його імені в Outliner — виділення й підсвітка спрацюють, навіть якщо він не видно у в’юпорті |

## Перед заняттям

- Blender 5.2 LTS встановлений (безкоштовний, працює на будь-якому ПК).
- Ноутбук без нампада? Перевір заздалегідь, що працює комбінація [[key:~]] для кругового меню видів — не всі клавіатури однаково реагують на емуляцію нампада.
- Спеціальної підготовки більше не потрібно: це заняття саме для того, щоб уперше відкрити Blender без страху щось зламати.
